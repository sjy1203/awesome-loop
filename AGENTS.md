# Instructions for agents

This repository is a curated, machine-readable list of looped and recurrent-depth language model papers. The YAML
files are the source of truth; everything else is generated by `scripts/build.py`.

## Layout

- `papers/<id>.yaml`: one paper. `id` is the arXiv id without version (quoted in YAML), or a lowercase slug for
  non-arXiv sources such as a lab blog post. `tier: deep` is a full card, `tier: radar` a light entry.
- `models/<id>.yaml`: one open-weight model family.
- `claims/<id>.yaml`: one open question with evidence from several papers.
- `schema/*.schema.json`: field definitions. `schema/vocab.yaml`: every allowed value and its meaning.
- `data/candidates.json`: new arXiv papers found by `scripts/discover.py`, waiting for triage.
  `data/rejected.txt`: ids triaged out of scope.
- Generated, never edit by hand: `README.md`, `README.zh-CN.md`, `docs/`, `assets/glyphs/`, `data/papers.json`,
  `data/models.json`, `data/claims.json`, `llms.txt`, `llms-full.txt`.
- `assets/banner.svg` and `assets/banner.zh-CN.svg` come from `scripts/banner.py`; edit the text there and rerun it.
- `data/trend.json` (quarterly arXiv counts for the trend chart) comes from `scripts/trend.py`; metrics come from
  `scripts/fetch_metrics.py`. Both run daily in `.github/workflows/metrics.yml`.
- The rankings at the top of the README (trending in the last 30 days, top 10 by impact score) are computed by
  `scripts/build.py` from `data/metrics/latest.json`; the weights are `SCORE_WEIGHTS` there. Only `focus: core`
  papers are ranked.
- Radar entries may carry `facets` with `placement`, `depth_train` and `kv`; they feed the design-space table.

## Scope

In scope: a learned layer, block or module is reused across depth within one forward pass, or its output state is
fed back through the same layers. Out of scope: agent loops, repeated full-model calls, and ordinary sequence
recurrence that only carries memory across tokens.

Deep cards are for language models (including code and multimodal language models). Papers from other domains go
in as radar entries.

## Adding or updating an entry

1. Read the source: `https://arxiv.org/abs/<id>` for metadata, `https://arxiv.org/html/<id>v1` (or the PDF) for
   the text and tables.
2. Copy `papers/2611.13378.yaml` as a template for a deep card. A radar entry needs only `id`, `tier`, `title`,
   `date`, `authors`, `links`, `category`, `focus`, `tldr` and `added`.
3. Run `python3 scripts/build.py`. It validates every file first; fix what it reports.
4. Commit the YAML together with the regenerated files. CI runs `python3 scripts/build.py --check`.

## Content rules

- Public sources only: the paper, its official code, model cards and official blog posts. Never add unpublished
  results, private experiments, or research ideas that are not in the source.
- Numbers are copied exactly as printed, each with a `ref` (Table N, Figure N, Section N, Appendix X). Do not
  compute differences, ratios, unit conversions, extrapolations or any other derived number. If the authors did
  not print it, leave it out.
- `budget.matched` lists what the main looped-vs-baseline comparison holds fixed; `budget.not_matched` lists what
  visibly differs; `baseline_tuned` is `separate` only when the paper says the baseline got its own tuning.
- `quickread.caveats` are factual limitations visible in the source: scale, context length, what was not matched,
  evaluation protocol, what the authors say they did not test. No speculation or advice.
- `quickread.hooks` holds only open questions that the authors state themselves.
- Bilingual fields: `en` and `zh` say the same thing, and bilingual lists have the same number of items. Keep
  standard terms such as KV, SWA, MoE, BPB and prefill in English in the Chinese text.
- `status: draft` until a second pass has re-checked every number against the source; then `verified`.
- `claims/*.yaml`: each evidence item names a paper in `papers/`, its setting (scale, tokens) and the finding in
  the paper's own numbers, with a ref.
- YAML: quote ids and dates, and quote any string that contains `: `. Keep each Chinese string on one line;
  a folded line break would put a space between two Chinese characters, which the validator rejects.

## Focus: core or related

Every paper sets `focus`. `core`: the paper is about a looped or recurrent-depth Transformer for language or general
reasoning (building, training, scaling, analyzing or serving one); multimodal language models and puzzle or
algorithmic reasoners built from looped Transformer blocks count. `related`: loops in other domains or modalities
(vision, 3D, audio, wireless, medical imaging, recommendation, tabular data, robotics, embeddings), RNN-, CNN- and
GNN-era precursors, implicit models outside language, layer sharing used only to save parameters, and every
`adjacent` paper. Deep cards are always `core`. Related papers stay in the collection but are not ranked.

## Triage of radar candidates

For each entry in `data/candidates.json`, either add `papers/<id>.yaml` (radar or deep), or add the id to
`data/rejected.txt` with a short reason. `scripts/discover.py` drops triaged ids from the queue on its next run.
